    Progress against goals

    This page answers one question: how far is Hebog from the goal its implementation plan defines for 1.0.0? It is updated whenever the plan's current state changes, and was last updated on 17 October 2026 after the 0.22.0 release. The scientific and performance measurements retain their original dates. Every figure is development evidence from the maintainer's machine, dated and traceable to versioned evidence and Git history; none is scientific qualification. User-facing limits are in capability and status.

    At a glance

    1.0.0 goal Target Position on 17 October 2026 Status
    Telescopes Standard FITS continuum images from any telescope under a documented header contract, validated on LOFAR and SKA-Mid for 1.0.0 and on SKA-Low precursor data at the later release whose envelope admits it The input header contract is defined and tested. LOFAR (LoTSS-DR3 and LoTSS-DR2) and SKA-Mid (SDC1 simulation) images run; MeerKAT MIGHTEE images fit the envelope; the only SKA-Low precursor mosaic (GLEAM-X) needs the 45,000-pixel tier and a position-dependent PSF, whose effect is to be measured and documented. A beam wider than 10 pixels is refused; every real Rapthor image in the archived cluster runs is at most about 7 pixels, and only Rapthor's synthetic demonstration sector (30 pixels) exceeds the limit. In progress

All 12 frozen public behaviours are implemented. Rapthor's Hebog branch calls the adapter in-process with a ThreadExecutor, memory admission, typed PyBDSF fallback and dual runs, tested through its real Prefect task on a single-threaded Dask worker. On a Rapthor branch; not merged
    Science A truth-based Rapthor retained/rejected gate, with limits set from the agreement check's truth measures, and a powered, held-out parity study against pinned PyBDSF master on LOFAR, SDC1 and MIGHTEE images inside the envelope Isolated-source position, flux and axis limits are met against both PyBDSF references on the frozen input, for sources and components under both profiles; the Total_flux limits hold on independent realizations. Two bounded known differences and one open defect remain. Rapthor keeps or rejects alike with Hebog's mask and pinned master's 92.8% of sky-model components under the chosen compact profile with a zero background; released PyBDSF reaches 99.29%, so the former 99.5% target was retired on 16 October for a truth-based gate. Against truth, that profile keeps injected sources as often as master or more and measures their flux within 1.5% from 10σ, but loses 5.1% of master's real components on extended sources and 3.5% at image edges, and finds 1.03% false islands on negated images against master's 0.64%, failing the truth-based limits set on 17 October in those three places. Development evidence only
    Performance The source-finding part of Rapthor's filter_skymodel step, from the task's start to LSMTool's filter_sources call, ≤0.50 of pinned PyBDSF master's, like for like on one node and across the nodes Rapthor deploys, for sectors up to the 1.0.0 envelope; the complete step reported beside it The gate fails. On a 3,000² LoTSS-DR3 window with four cores (emulated x86-64), Hebog's finder part is 2.43 times master's on Rapthor's thread path (162 s against 67 s; complete step 2.03) and 1.99 on four Dask workers in one repetition (171 s against 86 s); both burn about the same CPU, so four cores cannot pass the gate whatever the occupancy. On the 10,000² anchor with four Dask workers (16 October, one repetition) the finder part is 1.23 (1,249 s against 1,019 s; complete step 1.19), both finders keeping about three of four cores busy and Hebog using 11% more CPU; PyBDSF could not run the 15,402² mosaic in the 16 GB container VM. The dense 14,175² ELAIS-N1 sector took 8.5 h serially on 11 October, mostly in association; with the same settings it takes 2.0 h at 0.22.0, and 1.3 h under the compact default. On a local Dask cluster one sector takes 0.36 of one worker's time at four workers and 0.32 at six, with a 20% serial share; twelve threads are barely faster than one, and four Dask workers gain nothing on a 3,000² sector of four tiles. No regression on the Hebog curve. Gate failing
    Scalability The 22,500² tier for 1.0.0, covering Rapthor's default sectors, with one sector scaling across 1, 2, 5 and 10 nodes with invariant products; 45,000² on the 18 GiB development machine and 90,000² on the cluster as later minor releases; planner bounds for 100,000² on 100 to 200+ nodes Public envelope 15,402². Every stage runs tiled through the executor and products are byte-identical across tilings and executors. The traced peak is 1.7 GiB on the whole 15,402² mosaic and still grows about 1.7 bytes a pixel, which forecasts about 2.1 GiB at 22,500². Every task declares its memory, and the analysis's own records grow with the sources found, about 42 KB each. Bright regions are refined in bounded blocks, so the ELAIS-N1 deep field's central 5,000², where 951 bright candidates chain across the image, completes under four 4.5 GiB Dask workers. Nothing beyond one machine has run. 15,402 of 22,500 pixels
    Release PyPI, with portability, security, licensing, documentation and independent acceptance, under a 1.x compatibility policy v0.22.0 (17 October 2026) is the first release on PyPI, published with attestations; it passed its release check on 15 October and installs from PyPI on Python 3.12 and 3.14. Earlier releases are on GitHub and TestPyPI. CI runs on Linux, macOS and Windows for Python 3.12 to 3.14, and main requires the lowest-dependency and container checks. Experimental 0.x

    Functionality

    The 12 frozen public behaviours in config/contracts/phase-0-public-behaviours.json each name the test that holds them, and all 12 are implemented. A placeholder would be a strict xfail, so CI fails the day one starts passing.

    Behaviour Status
    A valid request returns versioned catalogue, RMS, mask, diagnostics and timing records Implemented
    An empty image succeeds with zero sources and structurally valid empty products Implemented
    Invalid beam, WCS, unit or dimensional metadata fails before any result is written Implemented
    Raising a threshold cannot create a source Implemented
    Tile shape, worker count, completion order and batch size do not change the products Implemented
    No worker materialises a complete large plane and admitted memory bounds the peak Implemented: every task declares its memory and none holds more
    Rapthor adapter products for the true-sky and flat-noise pair Implemented
    Retry reuses valid stage products Implemented
    Worker loss is retried to the same deterministic products Implemented

    Dual-run mode keeps products separate and reports differences Implemented on Rapthor's Hebog branch; reports both filtered product sets and retains their originals
    A cancelled analysis stops its tasks and removes its staging Implemented, under the Thread and Dask executors

    hebog.adapters.find_sector_sources runs one Rapthor sector on the caller's executor and writes Rapthor's four files. Rapthor's Hebog branch adds the native task on today's worker layout; its distributed path is planned. The integration evidence records the upstream audit, real Prefect/LSMTool/subprocess tests and the frozen-field checkpoint under both profiles and background settings. At the pins of 17 October (Rapthor aff26023, LSMTool 156ae6a), the integration container with Hebog 0.22.0 from PyPI passes 39 native/CLI tests; the broader native/settings suite passes 94, with full branch-aware coverage of the new native module, and Rapthor's library, operation and image-flow suites pass 662. Its parset defaults to the compact profile with a zero background. The 18-case quick science check has no regressions and all 54 FITS products match the previous baseline byte for byte. That three-source smoke check did not decide the profile; the agreement check did, below. The adapter's eight-column codec reads the catalogue find_sources writes. A continuum source of one fitted Gaussian publishes that Gaussian, so its row passes the three cuts Rapthor applies (DC_Maj, E_RA, E_DEC), as a compact row does; a source of several components leaves them empty, which on the agreement check's cases dropped 151 to 168 sources pinned master keeps. Under compact, which Rapthor runs, every source is one Gaussian.

    Agreement with master is compatibility, not correctness, so the check also measures every finder against known truth (run t76-truth-5, 17 October, 1,222 s with cached references, inside its one-hour budget).     compact keeps injected sources as often as master or more at every level and measures their flux within 1.5% from 10σ. Most of its disagreements with master lie between 5 and 7σ, where it also keeps sources master drops. Above 7σ it loses real components on extended sources, where its masks cover 64% of the ideal mask's pixels against master's 76%, and where the image edge cuts a source. Its RMS reads more than 20% low at 3.0% of real-image pixels against master's 1.9%, which gives it 60% more false islands on the negated images. continuum covers the most emission and finds the fewest false islands, but keeps 62% of injected 7σ sources and 77% at 10σ: its 35-pixel local-noise windows take faint sources for noise. The truth-based gate's limits, set on 17 October from these figures, are in the plan's scientific gates; released PyBDSF passes them and every Hebog lane fails.

    Open scientific defects

    • Clipped RMS reads low. The clipped window RMS has no truncation correction: on noise alone it reads 1.6% low on white noise and 3.2 to 3.9% low on beam-correlated noise (7 October).
    • Fixed meshes (deferred). Beams wider than 10 pixels are refused; scaling the meshes with the beam would recover sources to 22 pixels at about 2.5 times the local-noise read.

    Blockers and next steps

    The largest risks to 1.0.0 are the performance gap, which only many cores can close; memory that grows with the image and the sources found; the development machine's memory, disk and container VM; upstream churn; and the three steps outside the agent's control: cluster time, Rapthor's worker layout and independent reviewers. The plan's decisions pending list what the maintainer has still to decide, each with a recommendation.

    The next actions, as the plan orders them on 17 October:

    1. Agent: raise the 22,500² tier unattended; then one sector across the cluster, starting with a stage profile of the 10,000² anchor in the matched container and sizing tiles and task counts from the core budget and the memory a core needs, in four increments that each release.
    2. Human: push Rapthor's Hebog branch, which testing and trials use without waiting for a merge; file the Astropy report drafted on 5 October; take the pending decisions.
    3. Agent: the deployment envelope, the matched benchmarks on the cells the VM holds, the store and planner work and the cluster benchmark's packaging; the gate itself is measured on the cluster. Scientific improvements (the continuum local-noise repair, the clipped-RMS correction and the varying PSF) wait until this work is complete unless an output is confirmed incorrect.

    Keeping this page current

    Update this page in the same change as the plan's current-state table: after a release check, a tier gate, a new quick-check baseline or a repaired defect. The commands that produce the figures are just quick-science-check, just quick-benchmark and just traced-peak, described in Contribute to Hebog; the equivalence lane is just test-equivalence. Record the run label and date beside each figure and replace stale figures. Keep measurements in existing versioned evidence records or controlled storage, with exact identities linked from the commit. Git history preserves previous summaries.
